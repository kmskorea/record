# Record — 하루 기록

하루를 기록하고, 쌓인 기록에서 내 패턴을 찾아보는 개인용 앱.
브라우저만 있으면 노트북에서도 휴대폰에서도 열리고, 홈 화면에 설치하면 앱처럼 쓸 수 있습니다.

## 화면 구성

하단 버튼 3개로 이동합니다.

### 흐름 (왼쪽)

- **달력** — 날짜마다 그날 매긴 **하루 점수(0.5~5점)**에 따라 색이 칠해집니다. 5점에 가까울수록 진한 파랑, 2.5점이 흰색, 0.5점에 가까울수록 진한 빨강입니다. 점수는 안 매겼지만 뭔가 기록한 날은 작은 점, 일정이 걸린 날은 오른쪽 위에 점으로 표시됩니다. 운동한 날은 **왼쪽 위에 점**이 찍히는데, 근력은 초록·러닝은 노랑으로 나뉘고 둘 다 한 날은 두 개가 나란히 찍힙니다. 날짜를 누르면 그날 기록을 전부 펼쳐 보고 바로 고칠 수 있고, 지난 날·앞으로의 날 모두에 **일정(약속·마감·할일)**을 걸 수 있습니다.
- **트래킹** — 하루 점수, 수면시간, 컨디션, 운동량, 식사량, 몸무게, 단백질, 수분, 크레아틴, 당분, SNS 시간(합계·인스타그램·유튜브), 러닝 거리·페이스, 독서(읽은 쪽수)를 시계열로 봅니다. 항목을 **여러 개 누르면 겹쳐서** 그려지고, 아래에 두 항목의 실제 상관계수가 함께 나옵니다. 기간은 7 / 30 / 90일.
- **다가오는 일정** — 앞으로 걸려 있는 약속·마감을 모아 보여줍니다. 달력을 넘기지 않아도 됩니다.
- **시간을 어디에 썼나** — 최근 30일간 유형별 시간 비중과 하루 평균 시간.
- **점수를 가른 시간** — 어떤 시간을 1시간 이상 쓴 날이 그렇지 않은 날보다 몇 점 높았는지. 상관계수보다 직관적으로 읽힙니다.
- **인사이트** — 달력과 그래프만으로는 안 보이는 것들:
  - 연속 기록 일수, 평균 컨디션·수면, 운동한 날, 할일 완수율
  - 하루 점수 분포 (좋음/보통/별로 비율)
  - 요일별 평균 컨디션 — "금요일이 가장 좋고, 수요일이 가장 힘들었어요"
  - **발견** — 기록이 겹치는 항목쌍을 전부 훑어서 관계가 뚜렷한 것을 자동으로 찾아줍니다
  - 최근 자주 만난 사람

### 오늘 (가운데)

- **사전 관리** — 오늘 할 일(체크박스, 추가·삭제) / 수면(취침·기상 시각을 넣으면 잔 시간 자동 계산) / 컨디션 5단계와 그 이유
- **하루 중** — 아이디어. 떠오를 때마다 한 줄씩, 시각과 함께 쌓입니다
- **사후 관리** — 운동(여부, 부위 다중선택 + 직접 추가, 강도 3단계, 메모. 부위에서 **러닝**을 고르면 거리(km)와 1km 평균 페이스를 적는 칸이 딸려 나오고, 둘 다 적으면 걸린 시간을 계산해 보여줍니다) / 몸무게 / 식습관(끼니별 시각·양 5단계 + 단백질·수분·당분 각 5단계, 크레아틴은 O·X) / 관계(사람을 여러 명 한 번에 골라 같은 내용을 기록. 그날 약속이 있으면 위에 뜨고, 누르면 그 사람들이 골라진 채로 있었던 일을 적을 수 있습니다) / **콘텐츠**(안 보는 날이 더 많아서 눌러야 열립니다. 유형을 먼저 고르면 그 유형에 맞는 칸만 나옵니다 — **독서**는 읽은 쪽수·인상적인 구절·생각, **영화**는 별점·소감, **유튜브 영상**은 링크·영감. 유형은 직접 추가할 수 있고, 그때 어떤 칸을 받을지 골라둡니다. 작품 하나하나가 사람과 마찬가지로 객체라, 검색에서 누르면 거기에 적은 것이 한 번에 모여 보입니다) / 자기성찰 일기
- **하루 마무리** — **하루 시간표**에서 24시간을 30분 단위로 칠해 어디에 시간을 썼는지 남기고(유형은 직접 추가), **SNS 사용 시간**에 인스타그램·유튜브 스크린 타임을 적고, **하루 감상평**에서 0.5~5점 별점과 한 줄 평을 남깁니다. 이 점수가 달력 색이 됩니다.

### 검색 (오른쪽)

기록한 모든 글에서 단어를 찾습니다. 할일·아이디어·컨디션 이유·운동 메모·관계 기록·콘텐츠(구절과 소감)·일기가 모두 대상이고, 검색어는 결과에서 하이라이트됩니다. 사람 이름이나 작품 제목으로 찾으면 그에 얽힌 기록이 전부 걸립니다. 위쪽의 사람·콘텐츠 프로필을 누르면 지금까지 그에 대해 적은 것만 모아 볼 수 있습니다.
사람은 프로필로 따로 뜨고, 누르면 **그 사람에 대해 적은 모든 내용**을 한 번에 볼 수 있습니다.

### 알림

설정(오늘 탭 우측 상단 톱니)에서 켭니다. 기본값은 아침 9:30(할 일 정리), 밤 11:30(하루 마무리)이고 시각은 바꿀 수 있습니다.

> 브라우저 알림은 앱이 열려 있거나 백그라운드에 살아 있을 때 도착합니다. 홈 화면에 설치해두면 더 안정적입니다. 앱을 완전히 종료한 상태에서도 확실히 받으려면 푸시 서버가 필요합니다.

## 두 기기에서 쓰기

정적 사이트라서 아무 정적 호스팅에나 올리면 됩니다.

- **GitHub Pages** — 저장소 Settings → Pages → Source를 **GitHub Actions**로 바꾸면 `main`에 푸시될 때마다 `.github/workflows/deploy.yml`이 자동 배포합니다.
- **Vercel / Netlify / Cloudflare Pages** — 빌드 명령 `npm run build`, 출력 폴더 `dist`.
- 하위 경로(`example.com/record/`)에 올릴 때는 `BASE_PATH=/record/ npm run build`.

배포한 주소를 휴대폰 사파리/크롬에서 열고 **홈 화면에 추가**하면 앱 아이콘으로 실행됩니다.

### 기록은 어디에 저장되나

**기기에 먼저 쓰고, 그 다음 서버로 올립니다.** 두 곳 모두에 사본이 있습니다.

- 로컬(localStorage)이 즉시 반영되는 쪽입니다. 비행기 모드에서도 기록이 됩니다.
- 로그인하면 Supabase가 원본 저장소가 되어 노트북과 휴대폰이 같은 기록을 봅니다.
- 아직 못 올린 기록은 목록에 남겨두고 연결이 돌아오면 다시 올립니다. 올리기에 실패해도
  로컬 기록은 그대로입니다.

로그인하지 않아도 앱은 그대로 동작합니다. 그때는 이 기기에만 쌓입니다.

### 동기화 설정 (한 번만)

1. [supabase.com](https://supabase.com)에서 계정을 만들고 새 프로젝트를 생성합니다.
2. 프로젝트의 **SQL Editor**에 [`supabase/schema.sql`](supabase/schema.sql)을 통째로 붙여넣고 실행합니다.
3. **Settings → API**에서 `Project URL`과 `anon public` 키를 복사합니다.
4. 키를 앱에 알려주는 방법은 두 가지입니다.
   - **저장소에 넣기(권장)** — GitHub 저장소 Settings → Secrets and variables → Actions에서
     `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 두 개를 추가합니다. 이후 배포되는 앱은
     어느 기기에서 열든 로그인만 하면 됩니다.
   - **앱에서 직접 입력** — 설정 → 기기 간 동기화에 붙여넣습니다. 기기마다 한 번씩 입력해야 합니다.
5. 앱 설정에서 이메일·비밀번호로 가입하고 로그인합니다. 다른 기기에서도 같은 계정으로 로그인하면 됩니다.

로컬 개발은 `.env.example`을 `.env`로 복사해 값을 채우면 됩니다.

> **이미 쓰고 있다면**: 2번을 한 번 더 실행해 주세요. `schema.sql`은 통째로 다시 실행해도
> 안전하고, 예전에 쓰던 `people`·`content` 테이블의 내용을 새 `objects` 테이블로 옮겨 담습니다
> (옛 테이블은 지우지 않고 그대로 둡니다). 아직 실행하지 않은 동안에도 하루 기록은 평소대로
> 오가고, 사람·콘텐츠만 이 기기에 남아 있다가 스키마를 만든 뒤 그대로 올라갑니다.
> 그 상태면 설정 화면에 안내가 뜹니다.

> anon 키는 브라우저 번들에 들어가는, 공개되어도 되는 값입니다. 실제 접근 제어는 DB의
> RLS 정책(`auth.uid() = user_id`)이 합니다. 다른 사람이 키를 알아도 남의 기록은 못 읽습니다.

### 충돌이 나면

같은 날을 두 기기에서 고치면 **나중에 고친 쪽이 남습니다.** 하루 기록이 한 덩어리라 그렇습니다.
서로 다른 날이나 다른 사람에 대한 기록은 양쪽 모두 살아남습니다.

어떤 경우에도 서버에 없다는 이유로 로컬 기록을 지우지 않습니다. 올리기를 먼저 하고 내려받기 때문에,
아직 못 올린 수정이 오래된 서버 값에 덮이는 일도 없습니다.

### 왜 테이블이 세 개뿐인가

기록할 **내용**이 늘어나는 것과 새로운 **종류의 대상**이 생기는 것은 다릅니다.

- 하루 기록은 날짜당 JSON 한 덩어리라, 칸을 아무리 추가해도 서버는 그대로입니다.
- 사람·책·영화처럼 날짜에 매달리지 않고 따로 서서 여러 날에 걸쳐 참조되는 것은 자기 줄이
  필요합니다. 이걸 종류마다 테이블로 두면 앱을 고칠 때마다 SQL을 다시 돌려야 하고, 그때까지
  그 기록만 동기화가 막힙니다. 실제로 두 번 겪었습니다.

그래서 이런 것들은 `objects` 한 테이블에 `kind`로 구분해 담습니다. 앞으로 새로운 종류가
생겨도 문자열 하나만 늘리면 되고, `schema.sql`은 다시 실행할 필요가 없습니다.

### 기록 항목을 새로 추가하려면

예를 들어 카페인을 넣는다면 순서대로:

1. `src/lib/types.ts` — 모델에 필드 추가 + `emptyDay()`에 기본값
2. `src/features/today/sections.tsx` — 입력 UI 추가
3. `src/lib/metrics.ts` — 그래프에도 띄우려면 `METRICS`에 항목 추가
4. `src/lib/search.ts` — 글자로 검색되게 하려면 `searchAll()`에 추가

### 고칠 때 기록이 날아가지 않게

코드를 고쳐도 기록은 남습니다. 브라우저 localStorage에 따로 저장되고, 배포해도 주소가 같으면 유지됩니다. 다만 세 가지를 주의하세요.

- **로그인해 두면 주소가 바뀌어도 기록이 따라옵니다.** 로그인하지 않은 상태라면 호스팅을 옮길 때 새 주소는 빈 상태이니, 옮기기 전에 설정 → 데이터 → 내보내기로 JSON을 받아두세요.
- **필드를 새로 추가하면 예전 날짜에는 그 값이 없습니다.** 저장된 기록은 그 시점 모양 그대로 읽히므로 새 필드는 옛 기록에서 `undefined`입니다. 읽을 때 `?? 기본값`을 붙이세요. 예전 기록을 한 번에 채우고 싶으면 `src/lib/storage.ts`의 `migrate()`에서 처리하면 됩니다.
- **로그인하지 않았다면 브라우저 데이터를 지울 때 사라집니다.** 로그인해 두면 서버에 남아 있어 다시 받아옵니다. 그래도 가끔 내보내 두면 확실합니다.

## 구조

```
src/
  lib/
    types.ts          데이터 모델 (하루 기록, 사람, 알림 설정)
    date.ts           'YYYY-MM-DD' 로컬 날짜 유틸, 달력 그리드
    storage.ts        localStorage 읽기/쓰기, 마이그레이션, 스냅샷, 동기화 대기열
    store.tsx         전역 상태 + 동기화/로그인 (React Context)
    supabase.ts       서버 접속 정보와 클라이언트
    sync.ts           올리기·내려받기·병합 규칙
```
